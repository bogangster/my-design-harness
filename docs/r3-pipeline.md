# 파이프라인 (pipeline)

> 기준: docs/r2-purpose.md, docs/story-work.md

## 단계

| 단계 | story-work | 입력 | 출력 | 컨셉 모드 | 확장 모드 |
|---|---|---|---|---|---|
| S1 리서치 | 1~2 | 화면 ID | `refs/<id>.md` (레퍼런스 + 가져올 패턴) | ✅ | ✅ |
| S2 설계 | 3 | refs + prd.md | `specs/<id>.md` (섹션·컴포넌트·PRD 필드·역할별 상태) | ✅ | ✅ |
| S3 제작 | 4, 6 | spec + design.md | `screens/<id>.html` (+ `system/` 토큰·컴포넌트) | ✅ ×3 | ✅ ×1 |
| S4 검토 | 7 | screen | `reports/<id>.json` — 스크립트 게이트 | ✅ | ✅ |
| S5 확정 | 5 | 키스크린 3개 + 리포트 | `system/APPROVED` — 사람 승인 | ✅ | ⏭ 건너뜀 |

- 컨셉 모드 키스크린: `home`, `my-assets`, `admin-review`
- 레퍼런스: 화면당 서로 다른 앱 5개 (uibowl)

## story-work와 다른 점

- 실제로는 컨셉 확정(5) → 토큰 제작(6) 순서였지만, 하네스는 S3에서 토큰을 먼저 만들고 S5 승인 시 `system/`을 잠근다. S4 스크립트가 처음부터 토큰을 셀 수 있게 하기 위함.
- 확장 모드에서 `system/` 수정은 사람 승인 필요.

## 되돌아가는 지점

| 실패 | 복귀 |
|---|---|
| S4 토큰 위반 / N1·N2 위반 | S3 |
| S4 PRD 필드 누락 | S2 |
| S4 G1 (레퍼런스 1개 과다 추종) | S1 |
| S5 거절 | S2 (코멘트에 `[ref]` 태그 있으면 S1) |
| 자동 재시도 | 단계당 최대 3회 → 초과 시 중단 + 리포트 |

## 후속 작업: 피그마 이관 (파이프라인 밖, 별도 트리거)

- 5단계 파이프라인이 끝난 화면만 대상. 트리거: "피그마로 옮겨줘" / "`<화면>` 피그마로 옮겨줘"
- 대상 조건: `system/APPROVED` 존재 + `reports/<id>.json` 전 게이트 pass
- 담당: figma-publisher (피그마 MCP로 HTML → 피그마 프레임 390×844)
- 판정은 HTML 기준으로 끝났으므로 피그마 쪽 게이트 없음
